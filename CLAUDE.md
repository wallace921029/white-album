## Repository layout

Two independent npm projects in one repo:

- **Root** — Vite 8 + React 19 + TypeScript 6 frontend. Dev server on port **5173**.
  - `src/App.tsx` is the top-level feature surface; `src/main.tsx` mounts it in `StrictMode`.
  - `src/components/ui/` is the full shadcn/ui set (`radix-nova` style, `lucide` icons). Reuse these before writing new primitives.
  - `src/lib/utils.ts` exports the `cn()` helper; `src/hooks/use-mobile.ts` backs the sidebar.
  - Styling: Tailwind CSS v4 via `@tailwindcss/vite`, imported in `src/index.css` (global tokens/typography). `src/App.css` holds page-level layout. Plain `.css` files use native CSS nesting — preserve that.
  - `@/*` path alias maps to `src/`.
- **`backend/`** — Fastify 5 API for the family album/notice center, written in **TypeScript** (ESM-style source, compiled to CommonJS in `dist/`). Dev server on port **3000**. Source lives in `backend/src/`; full API reference in `backend/doc/api.md`.
  - `src/app.ts` autoloads `src/plugins/` then `src/routes/`. Add features by creating files there, not by editing `app.ts`. Autoload maps each route subfolder to a URL prefix (`routes/auth/index.ts` → `/auth`). Production runs the compiled entry `dist/src/app.js`.
  - **Persistence**: **Drizzle ORM + better-sqlite3** (native module, ships prebuilt binaries — Docker needs no build toolchain). The schema is the single source of truth in `src/db/schema.ts` (camelCase TS keys → snake_case columns); SQL migrations are generated by `drizzle-kit` into `backend/drizzle/` and **applied by the migrator on boot** in `src/plugins/db.ts`. The drizzle instance is exposed as `fastify.db` (synchronous query builder: `.get()` / `.all()` / `.run()`). Photo files are written to the upload dir on disk; only metadata is in SQLite. DB file + uploads both sit under `DATA_DIR` so one Docker volume persists everything — **also deploy the `drizzle/` folder** (the migrator reads it at runtime).
  - **Plugins** (all `fastify-plugin`-wrapped so decorators are app-wide): `db.ts` (`fastify.db`), `auth.ts` (`@fastify/jwt` + `fastify.authenticate` / `fastify.authorizeAdmin` preHandlers; token payload on `request.user`), `app.ts` (CORS, multipart, `@fastify/static` serving `/uploads/*`, `fastify.uploadDir`), `sensible.ts` (`fastify.httpErrors`). Shared non-plugin helpers in `src/lib/` (`config.ts`, `password.ts` scrypt hashing, `serializers.ts` row→API mappers). Fastify/JWT type augmentations in `src/types/fastify.d.ts`.
  - **Auth model**: multi-user accounts, JWT in the `Authorization: Bearer` header. Registration is invite-code based, except the very first user (when the `users` table is empty) registers with no code and becomes the admin. Admins mint invite codes via `/invites`. Viewing content requires login; mutations require admin (messages can also be deleted by their author).
  - **Config** via env vars (see `backend/.env.example`): `DATA_DIR`, `DATABASE_PATH`, `UPLOAD_DIR`, `MIGRATIONS_DIR`, `JWT_SECRET` (set in prod — boots with an insecure dev default otherwise), `JWT_EXPIRES_IN`, `CORS_ORIGIN`, `MAX_UPLOAD_BYTES`.
  - **Tests** (`backend/test/**/*.test.ts`) use the in-memory DB (`databasePath: ':memory:'`) and a temp upload dir, wired in `test/helper.ts`; each `build(t)` is isolated and the migrator builds all tables fresh per instance.
- `corpora/` is currently empty.

There is no frontend router, state library, or frontend test framework — don't add one for small changes.

## Commands

Run both dev servers together (checks ports are free first, streams both logs, Ctrl+C stops both):
- Windows / PowerShell: `./dev.ps1`
- bash: `./dev.sh`

Frontend (run from repo root):
- `npm install`
- `npm run dev` — Vite dev server
- `npm run build` — `tsc -b` then `vite build`. **Preferred validation** after meaningful changes since it type-checks first.
- `npm run lint` — oxlint (config in `.oxlintrc.json`); secondary check.
- `npm run preview`

Backend (run from `backend/`, TypeScript):
- `cd backend && npm install`
- `cd backend && npm run dev` — `tsx watch` runs the TS source (`src/app.ts`) directly via the fastify-cli entry, restarting on change; no build step and no `dist/` needed for dev. tsx transpiles without type-checking, so run `npm run typecheck` (or rely on your editor) for type errors.
- `cd backend && npm run build` — `tsc` → `dist/`
- `cd backend && npm run typecheck` — `tsc --noEmit`
- `cd backend && npm start` — production (`fastify start dist/src/app.js`; build first)
- `cd backend && npm test` — `tsc` then `node --test "dist/test/**/*.test.js"`
  - Single test file (after a build): `cd backend && node --test dist/test/routes/root.test.js`
- **Drizzle**: edit `src/db/schema.ts`, then `npm run db:generate` to emit a new migration into `drizzle/`; `npm run db:studio` opens the DB browser. Migrations are auto-applied on server boot, so no manual `db:migrate` is needed for the app to run.

## Conventions that matter

- Match the existing template style: functional components, **no semicolons**, single quotes, simple local state.
- TypeScript strict mode rejects unused locals/parameters — remove dead code rather than leaving placeholders.
- `axios` is available in both projects.
- Keep backend work inside the Fastify CLI structure unless a larger reorganization is explicitly requested.
